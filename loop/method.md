# 手法の改善ログ

改善ループそのもの(ケース、審査、判定、手順)の変更を記録します。スキルの変更は `experiments.md` に書きます。各実験の後に「手法の振り返り」(`IMPROVEMENT.md` の手順5)を行い、手法を変えたらここに1エントリ足します。

## テンプレート

```
### M-NNN タイトル
- date:
- trigger: (どの実験の何がきっかけか)
- problem: (手法のどこが、誤った信号や無駄を生んだか)
- change: (何をどう変えたか)
- check: (次の実験で、効いたかをどう確かめるか)
```

## エントリ

### M-004 専門家の拒否権を2段階にし、和文の改行を JLReq で判断する
- date: 2026-10-31
- trigger: EXP-007、EXP-010 の不採用と、EXP-005〜010 の全審査の振り返り
- problem:
  - 和文の3件(02・03・05)では、ほぼすべての審査で D4 が2点に抑えられていた。理由は「本文が語の途中で折れる」。EXP-007(auto-phrase を全体に適用)と EXP-010(R19 で残りを列挙して直す)は、改行を減らしたが、審査は残りの1か所を見つけて同じく2点にした。スキル側をどう変えても動かない次元は、改善の信号にならない。
  - 審査プロンプトは、専門家の「具体的な欠陥」なら何でも上限2点にしていた。WCAG 違反と組版の小さな傷が同じ重さだった。
  - 日本語組版の標準(W3C JLReq)では、本文の仮名・漢字の間での改行は正しい組版で、禁止されるのは行頭・行末の禁則などに限られる。審査プロンプトの「改行と文節分割」は、この標準より厳しい、欧文の慣習に近い基準だった。
- change:
  - 専門家の拒否権を2段階にした。WCAG 2.2 AA 違反、または内容が読めない・誤読される欠陥は上限2点。組版の小さな傷は、目立つ場所か繰り返しのときだけ1点下げる。
  - 和文の改行は JLReq で判断する。欠陥は、禁則違反、数字と単位の分離、見出し・ボタン・ラベルなど1〜2行のテキストでの語の分割、見出しの1〜2字の最終行。
  - 審査条件が変わったので、新しい基準(v0.4.0 の生成)を作り、旧基準(v0.3.0)も同じプロンプトで審査し直して比べる。旧プロンプトの点数とは直接比べない。
- check: 新しいプロンプトで、和文3件の D4 が改行以外の理由(書体の選択、サイズ、行間)で点を分けるようになるか。英語の3件の点が旧プロンプトから大きく動かないか(動いたら、変更が和文以外にも効いている)。

### M-005 base は同じ版の複数の生成の平均にする
- date: 2026-10-31
- trigger: EXP-013・EXP-014 の不採用の振り返り
- problem:
  - v0.6.0 と同じ内容のスキル(v0.5.0 + EXP-012)で、学習用6件を2回生成していた(EXP-012 の run と v0.6.0 の基準 run)。合計は 88.1 と 91.3 で、3.2 点違った。主審査 Opus でも 49.0 と 50.3。ケース単位では 02 が 87.0 と 90.8、06 が 90.0 と 92.5。生成1回のばらつきは、採点のぶれ(M-003 で約1点)より大きく、これまでの仮説の効果(+1〜+2)と同じ大きさだった。
  - 高い方の1回(91.3)を base にすると、候補は平均への回帰だけで下がって見える。EXP-013 は −1.5、EXP-014 は −2.9 と表示された。逆に、低い方の1回を base にすると、効かない変更が採用される(EXP-005・008 が統合後に再現しなかった原因の候補)。
- change:
  - `compare --base` は、同じ版の run をカンマ区切りで複数受け取り、ケースごとに平均して base にする(合計、次元、審査ごとの点)。
  - 版を上げたあとの基準 run も、前の版の run と合わせず、その版で2回以上の生成がそろうまでは、その版と内容が同じ候補 run を base に加える。
  - 判定の規則(`eval/rubric.md`)は変えない。
- check: v0.6.0 の base(2回の平均、学習用 89.7)に対して、EXP-013 は +0.1(主審査 +0.5)、EXP-014 は −0.9(主審査 −0.5)。この規則を決めたのは2件の結果を見たあとなので、次の2件で、2回の base が判定を安定させるかを確かめる。候補も2回生成できれば一番よいが、利用上限を考え、効果が大きい候補だけ2回目を生成する。

### M-006 採点の撮影時刻を固定する
- date: 2026-10-31
- trigger: EXP-017 の 05(時刻表)が、日本時間 03 時台に撮影され、始発前の状態で審査された
- problem: `score` の render-check は実際の時計で撮影していた。時刻表、営業時間、締め切りのカウントダウンなど時刻で表示が変わるページは、採点した時刻によって別の状態が審査される。同じページでも、採点の時刻で D1・D3・D8 が動く。
- change: render-check に `--time`(ページの時計を固定する ISO の時刻)と `--tz`(ページのタイムゾーン)を追加した。`score` は、和文のページを 2026-11-04(水)10:30 の Asia/Tokyo、それ以外を同じ日の 10:30 の America/New_York で撮影する。生成役が自分で確かめるときは、従来どおり実際の時計で撮影する(craft.md の「時刻で変わる表示は代表的な状態に」はそのまま)。
- check: 以後の run は固定時刻で撮影される。固定時刻より前の run を base に混ぜるときは、時刻で表示が変わるケース(05、07、08、09)の差を割り引いて読む。
