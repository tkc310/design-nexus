## やめること

**繰り返している型**(EXP-076〜079)
- 利用者の好みを、利用者の例なしにループが代わりの指標で決め、「出すならどちらか」の審査で測る。
- 審査が仕事と読む中身(説得の文、節を分けるカード、選択肢を名指すラベル)を、好みのために消す。
- 勝ちを決める判断(狭い幅の第1画面、言葉)を安くして、費用を下げる。

**避ける規則**
1. **好み(文章の量、AI っぽさ)の実験は、利用者の例か利用者の確かめを関門に持つものだけにする。**(EXP-076、078、079)
   - 利用者がいない間は、情報を失わずに機械で測れる部分(言い直しの数、費用)だけを回す。
   - 確かめの材料は先に作っておく。
2. **消してよいのは、ページの中に同じ情報がもう 1 つあるものと、仕事のない飾りだけ。**(EXP-073、076、078)
   - 説得の文、節を分ける枠、選択肢や操作を名指すラベルは、好みのために消さない。
   - 機械で守れるもの(機能の文、第1画面)は、R35・R36 で守る。
3. **前提の確かめが外れたら、その実験は行わない。**(EXP-078)計画にも、外れたときの続け方を書かない。
4. **費用は、勝ちを決めていない部分から下げる。**(EXP-077、EXP-065・066)
   - 対象は、読み直し、広い幅の画面写真、重なった批評、二重の見直し。
   - モデルを下げること、見直しを省くことは、既定の出力にしない。利用者が選ぶ予算か、opt-in にする。
5. **一般の節に 1 文の心得を足して、行動が変わるのを待たない。**(EXP-079、EXP-009)その行動が起きる手順の場所に置き、道具の出力で手がかりを渡す(EXP-075 の accent.md と R35・R36 の形)。
6. **見直しの回数が違うページを対にしない。**(x079)run ごとに、ページごとの見直しの回数と、その起こし方を書く。
7. **前回から続ける規則**
   - 採用の関門を通った run を、基準点にしない。同じ基準点のページは 2 回まで(M-054、M-064)。
   - 束にしない。1 回の実験は 1 つの変更。却下した考えを、別の変更と組んで出し直さない。
   - 規則は、それが要るときだけ読まれるファイルに置く(面の規則は面のファイル、頼まれたときの規則はステア)。

### 4. H4: 作る本人と見直しで、画面の批評を重ねない((3)。H2 が外れたときだけ)

- **仮説**: standard で作る本人が自分で見直しを起動するときは、作る本人は手順 7 の画面写真の批評を行わず、批評を新しい目の見直しに任せる。こうすると、1 ページ(作る本人 + その見直し)の費用が 0.85 倍以下になり、今の版に負け越さない。

- **別の切り口である理由**: 判断を安くするのでも(EXP-077)、節約を指示するのでもない(EXP-072)。同じ批評を 2 回する形をやめる。EXP-071 では、見直しを足しても新しい生成では差がなかった。同じ手順 6〜8 の 2 回目に、費用ほどの効き目はない見込み。

- **対象ケース**: 01・03・05(marketing、product、mobile を 1 つずつ)。
- **変更先のファイル**: SKILL.md 手順 7 に 1 文を足す(英文は案): `In standard, when you will start the second look yourself (step 9), stop this step after the default-render check and the tool findings; the second look does the screenshot critique.`
  - 見直しを起動できないエージェントでは、今のとおり批評する(見直しが「残っている」まま出荷されるため)。
- **効果を確かめる方法**

### M-073 見直しは 1 ページ 1 回にし、起こし方を run に記録する

- **理由**: 診断 5。x079 では 12 ページとも見直しが 2 回になり、費用が約 3 割増え、11/16 までの run と比べられなくなった。
- **方法**: 実験ごとに、次のどちらかを登録で選ぶ。
  - **A(利用者の環境と同じ)**: 作る本人がサブエージェントで見直す。ハーネスが見直すのは、gen.json の `subagent_stats.spawned` が 0 のページだけ。見直しの前のページは残らない。
  - **B(11/16 までと同じ)**: 生成役をサブエージェントの道具を使えない形で起動し(`--disallowedTools` など)、ハーネスが `eval/second-look.mjs` で 1 回見直す。`_before/` が残る。
  - 共通の記録と制限
    - run.json に、ページごとの見直しの回数(spawned の数とハーネスの回数)と、A・B のどちらで起こしたかを書く。
    - `pair` は、見直しの回数が違うページの対を断る。理由を書いたときだけ通す。
  - 使い分け: 11/16 までの run と比べるときは B。x079 の `_before/` と比べるときは A(H1)。
- **費用**: コードだけ。生成を使う 12 ページの実験で、約 13 ドル(約 0.15)下がる。
