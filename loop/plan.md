## やめること

**繰り返している型**(EXP-059・061・062。前回の EXP-048〜053 も同じ)

- 直前の測定で負けた次元の理由を数件読み、その欠陥を消す 1 文を足すか替える。
- 6〜24 対の小さな net か、1 つの次元の net を関門にする。比べる基準点は 2 run だけで、しかも採用された run。
- 見込める効果は分解能に届かず、関門は硬貨投げになる。結果は、却下か、平均への回帰。

**避ける規則**

1. **直前の採用の測定で負けた次元を、次の仮説にしない。**
   - 次元は総合と 64〜83% 一致し、24 対で ±5 は動く(EXP-059 の D8、EXP-061 の D6)。
   - 仮説の元は、次の 3 つに限る。
     - 48 対以上の決め手の型の割合(M-057)。
     - M-048 で勝ちを予測すると確かめた性質。
     - 生成の手順の仕組み(生成役が何を見て、誰が確かめ、何をどの順に決めるか)。
2. **前の変更の副作用を、同じ段落への 1 文で消さない。**
   - 手順 1 の事実の段落は、3 回変えた(EXP-055・059・061)。
   - 副作用が残るなら、その変更自体を新しい変種として作り直し、前の版と比べる。でなければ、引き換えとして受け入れる。
3. **見込める効果が、測り方の分解能に届かない実験をしない。**
   - 事前登録に、2 つを並べて書く。効果の上限(その型が決めた対の割合 × 直る率)と、設計の分解能(M-055)。
   - 上限が分解能に届かなければ、前後の対(M-056)で測れる形にするか、行わない。
   - 1 文の変更を、全体の生成の 24 対で測らない。
4. **採用した候補 run を基準点にしない。** 基準点は、採用のあとに新しく作った 4 run(M-054)。
5. **6 ページ、ケースの部分集合、1 つの次元の net を、採否の関門にしない。**
   - 段階 1 は全 6 ケースで、大きな害で止めるためだけに使う(M-060)。
   - 次元の net は、守りの下限にだけ使う。

  - EXP-053 の型(行に操作を足して要約が下がり、D1 −6)。この変更は、操作を足せとは書かない。単位の値と計算をシグネチャにするだけで、要約(計算)はシグネチャの一部になる。D1・D3 を守りにする。

- **繰り返しでない理由**

  - EXP-053 は、行に操作を置く項を足した。EXP-032 は、仕事の表を足した。
  - この仮説は、2 か所の文を置き換えて、決める順番を変える。

### 4. H4: 方向を、描いた 2 つの第1画面から選ぶ(ばらつきを、選ぶことで減らす)

## 評価手法の改善案

method.md に M- として記録する前提。番号は仮で、M-054 から振る。

### M-054 採用のたびに基準点を 4 run 作り直す。候補 run を基準点にしない

- **理由**: 診断 2。EXP-059〜062 は、採用された候補 run(exp058a・b)を基準点にした。基準点 12 ページのうち 6 ページは、勝敗が固定していた。
- **方法**
  - v0.14.2 で、base142a〜d を同じ波で生成する。以後の対比較の基準点はこれ。採用の確認(M-031)は、base142a・b 対 base141a・b。
  - `pair --base` は、run.json の label が候補(exp…)の run を基準点に取らない。止めて理由を出す。
  - 推奨: base142a・b 対 base142c・d の 24 対を、両方の審査で A/A として測る。
    - M-055 のモデルの幅と比べる。
    - M-052・M-053 の審査文が、同じ版どうしで何を決め手にしているか(未確認の主張がどれだけ勝敗を決めるか)を見る(M-052 の残る疑い)。
- **費用**: 生成は約 5M(採用のたびに 1 回)。A/A は約 7M(1 回だけ)。

### M-055 関門を、ページの効果を入れた null から決める。次元の net と 2 つ目の審査は、狙いの関門にしない

- **理由**: 診断 1・3・5。24 対の「+4 以上」は、効果がなくても 2〜3 割通る。勝ちの率 0.6 でも、5〜6 割しか通らない。
- **方法**
  - `compare` が、設計(候補のページ数、基準点の run 数、1 ページあたりの対の数)から、次を出す。
    - 効果がないときの net の分布。
    - 勝ちの率 0.6・0.7・0.8 で、関門を通る率。
  - 分布は 2 通りで出し、厳しいほうを使う。二項と、ページの効果のモデル(見直し役の sim2.py の形。パラメータは過去の判定から毎回見積もる)。
  - 事前登録に、この率を書く。次の実験は行わない。
    - 効果がなくても、1 割を超えて通る関門。
    - 見込みの効果で、5 割に届かない設計。
  - 見込みの効果は、「その型が決めた対の割合 × 直る率」で上限を書く(M-057)。
  - 狙いの関門は、ルーブリックなしの一致した net だけにする(前回の M-043)。
  - ルーブリックは守りに使う。clear net と、名指した次元の下限(24 対で −9、48 対で −12)。
- **費用**: コードだけ。

### M-056 前後の対: 同じ出発点から手順 6 以降を腕ごとにやり直し、変わったページだけを審査する

- **理由**: 診断 1・4。ページのゆれが、1 文の効果より大きい。確かめと直しの手順の変更なら、同じページから始めれば、ページのゆれが両腕で消える。
- **方法**
  - `prepare --from <run> --skill <変種> --label <腕>` を作る。
    - 既存の run の index.html・NOTES.md・DESIGN.md を、出発点として写す。
    - PROMPT.md に「手順 6 以降だけを行う」と書く。
    - 出発点は、base142a〜d の 24 ページ。M-045 のとおり、確かめのあとの編集は 0 なので、出来上がりのページは最初に書いたページとほぼ同じ。
  - 腕は 2 つ。対照(今の手順 6・7 と今の道具)と変種。どちらも新しい文脈で、base と同じモデルと推論量。
  - 両腕でページが同じなら、引き分けにして審査しない。違う対だけを、ルーブリックなしは両順、ルーブリックありは片順で審査する。写しから NOTES.md と DESIGN.md は消す。
  - `compare --paired` が、次を並べる。
    - 変わったページの数。
    - 腕どうしの、一致した勝ち負け。
    - Floor と R の件数。
    - 費用。
  - 前後の対で採った変更は、M-031 の採用の確認で締める。
- **検出力**
  - 直したページの 8 割が良くなる変更なら、決着 16 対で約 8 割の確率で通る。
  - 全体の生成で測ると、同じ効果は勝ちの率 0.55〜0.65 に薄まり、今の形ではほとんど見えない。
- **費用**
  - 生成は、腕 1 つ 24 ページで約 1〜1.5M(確かめの分だけ)。
  - 審査は、変わった対の数 × 3 判定。16 対なら約 5M。
  - 通常の実験(生成 2〜3M と審査 7〜10M)より安い。
- **限界**: 新しい文脈でやり直すので、作った文脈で確かめる本番とは違う。ただし、違いは両腕に同じく入るので、腕どうしの比較は成り立つ。最後の確かめは M-031 で行う。

### M-057 審査役に、決め手の型を 1 つ選ばせる

- **理由**: 診断 3。仮説の元を、1 回の測定の次元ではなく、多くの対の決め手の型の割合から取るため。効果の上限も、前もって出せる。今は、理由の文のキーワードでしか数えられない。
- **方法**: pair-prompt.md と neutral-prompt.md の出力に `deciding_class` を足す。判定の文は変えない。選ぶのは、次の 8 つから 1 つ。
  - 狭い幅の壊れ
  - 答えの大きさと第1画面
  - 仕事をその場で済ませる
  - シグネチャの読みやすさ(凡例、何を指すか)
  - 見た目の独自性
  - 未確認の主張
  - 足りない中身(状態を含む)
  - その他
- **確かめ**(計器の変更、EXP-049 の型): 審査済みの 24 対を、足した形で審査し直す。総合の勝者の一致が 0.85 以上なら採る。
- **費用**: 確かめに約 3M。以後は 0。

### M-058 事実の照合に、ブリーフが渡す素材を入れ、照合の出力を run に残す

- **理由**: 診断 5・6。06 の 4 ページが 8 件以上と数えられたのは、照合が hero.png の盤面を読まないからである見込みが高い。照合の出力も残っていない。
- **方法**
  - 照合の入力に、ブリーフが渡した素材の見える文を、依頼が与えた事実として入れる。06 では hero-source.html の文と SOURCE.html の文。
  - 結果を、各ページのフォルダに `facts.<model>.json` で書く。中身は、挙げた主張、根拠の有無、見本か製品の事実か。
  - 06 の既存の 8 ページ(base141a〜d、exp058a・b、exp062a・b)を数え直す。8 件未満に下がれば、「06 は事実を足し続ける」は計器の誤りとして記録する。
  - 主張の扱いのぶれを数える。
    - 同じページを含む対のあいだで、同じ主張が減点と加点に割れる率を出す(EXP-062 の 02 の「13:30 開始」「最寄り駅」)。
    - 2 割を超えたら、neutral-prompt.md の項の書き方を見直す。直すときは、基準点どうしの対で先に動きを測る(やめること 9)。
- **費用**: 約 0.5M。

### M-059 生成の環境を記録し、スキルのサブエージェントの指示が働く形で生成できるようにする

- **理由**: 診断 4。生成役はエージェントの道具のないサブエージェントで、「新しい文脈の見直し」と EXP-032 の初見テストは、自分の見直しに落ちていた。利用者の Claude Code では働く指示を、評価では一度も測っていない。
- **方法**
  - run.json に、生成役の記録から次を書く: generator_model、エージェントの道具の有無、読んだ画像のファイル名と大きさ。
  - H2 の採用の確認では、生成を、サブエージェントを起動できる形(トップレベルのセッション)で行う。
  - それができない間は、M-056 の前後の対で、ハーネスが見直しの文脈を起動して代える。
- **費用**: 記録は 0。トップレベルの生成は、トークンは同じで、並べて走らせる段取りが要る。

### M-060 段階 1 は全 6 ケースで、止めるためだけに使う

- **理由**: 診断 1〜3。
  - EXP-061 の段階 1 は LP の 3 ケースだけで、02 の弱い基準点のページが差の大半を作った。
  - EXP-059・061 は、段階 1 に 1 つの次元の net を置いた。
- **方法**

- **費用**: 0。
