## やめること

**繰り返している型**(EXP-067・071・072・073)

- 採用された run を基準点にし、3〜4 回使う。null の中心がずれ、効果のない変種まで落ちる。
- 審査が見ない性質の依頼を全ページの既定の出力に入れ、「基準点に勝つか」と審査の次元で測る。
- 予想した失敗を但し書きで止めようとし、いくつもの変更を 1 つの関門で測る。

**避ける規則**

1. **採用の関門を通った run を、基準点にしない。基準点のページは 2 回まで(M-054)。**
   - exp065a・b と exp066a・b は、以後は採否の基準点に使わない。ステアの試験の出発点には使ってよい(M-067)。
   - `pair --base` に guard が入るまで(M-064)、登録に各基準点の使用回数を書く。
2. **束にしない。1 回の実験は 1 つの変更。** 費用は、範囲を絞った設計(変更が届くケースだけ、既存のページに当てるステアの試験)で下げる。
3. **却下した考えを、別の変更と組んで出し直さない**(EXP-072 のタイルは、EXP-063 で 9–7 の REJECT)。
4. **規則は、それが要るときだけ読まれるファイルに置く。**
   - 全ページが読むファイル(SKILL.md、craft.md、手順 7 から読む audit.md)と second look に足すのは、全ページに要る規則だけ。
   - 面ごとの規則は面のファイルに、頼まれたときの規則はステアのファイルに置く。
5. **予想した失敗を、但し書きの文で止めない。**
   - 機械で見つかる失敗(押し下げ、消えた数字や文言、字の漏れ)は、道具で止める。
   - 機械で見つからない失敗が予想されるなら、その変更は opt-in にする。
6. **利用者の好み(速さ、トークン、文の量、アクセント、AI っぽさ)を、「基準点に勝つか」で採否しない。**
