# 月次の収集手順

`docs/design-trends/` を 1 か月に 1 回更新するための手順です。デザイン作業のたびに読むファイルではありません。スキルが流行を採用するかどうかの判断は [README.md](README.md) の「採用前の評価」です。

日時はすべて JST で書きます。UTC のまま残すときだけ（UTC）と書きます。反応数とスター数には、取った日時を残します。

## 役割

- **Web** は、このリポジトリを触るクラウドエージェントが集めます。対象は業界レポート、公式ドキュメント、論文です。投稿のまとめサイトや未確認の転載だけで確度を上げません。
- **X（公開投稿）** は、Cursor とクラウドエージェントからは開けません。タイムラインも検索も、この環境の収集手順には入れません。X は Takashi の Grok Bot アシスタントが外で集め、入力ファイルとして渡します。クラウドエージェントはそのファイルを Web の調査と突き合わせてマージします。ファイルが無い月は、X の反応数を新しく書いたことにせず、Web だけで更新したことと、X は未更新であることを `monthly/YYYY-MM.md` に書きます。

## 入力ファイル `x-findings-YYYY-MM.md`

渡す場所は、会話への添付でも、作業ツリー上のパスでもかまいません。正本の項目ファイルにはしません。マージが終わったあとにリポジトリへ残す場合は `docs/design-trends/inbox/x-findings-YYYY-MM.md` に置きます。inbox が無くても DB は成立します。項目の「ソース」には、入力ファイル名ではなく投稿 URL を書きます。

書式は次のとおりです。投稿が複数なら「## 投稿」を繰り返します。いいねと表示が取れていない投稿は、数値を空欄のまま推定で埋めず、「取得できず」と書きます。

```markdown
# X findings YYYY-MM

- 収集者: Takashi's Grok Bot assistant
- 収集日時: YYYY-MM-DD HH:MM JST
- 検索の範囲: YYYY-MM-DD 〜 YYYY-MM-DD（JST）。公開投稿。クエリや min_faves を使った場合はその条件も書く

## 投稿

- URL: https://x.com/<handle>/status/<id>
- 投稿日時: YYYY-MM-DD HH:MM JST
- 著者: @handle
- いいね: 120
- 表示: 34000
- リポスト: 15
- ブックマーク: 40
- メモ: 何を根拠にできるかを 1〜3 文。投稿がそう主張していることと、本文から確認できたことを分ける。
- 関連: T08
- 見送り: 任意。反応が小さい、本文がリンクだけ、期間外、など

## 検索したが項目にしなかったもの

- URL と、見送る理由を 1 行。反応数が取れていれば添える。
```

必須は URL、投稿日時（JST）、著者、いいね、表示、メモです。リポストとブックマークは取れたときだけ書きます。関連は既存 ID、または「新規」です。

2026-10 分は、すでに各項目のソースへ展開済みです。同じ投稿を次月に再掲するときは、取り直した数値と収集日時を書きます。10 月のスナップショット（12:45 JST 頃）を、新しい月の数値として流用しません。

## 確度

根拠の弱いものは下げ、確認できなかったものは「未確認」にします。段階は次の 6 つだけです。

| 確度 | 付けるとき |
|---|---|
| 高 | 公式ドキュメント、論文、業界レポートのどれかと、期間内の X で反応のある投稿が複数あり、互いが食い違わない。X が無くても、一次資料が複数で一致していれば高にしてよい。その場合は「X の話題量」を本文に残す |
| 中〜高 | 一次資料か X の片方が強く、もう片方が弱いが矛盾しない |
| 中 | 単一のレポートが中心、または X の反応が小さい |
| 低〜中 | レポート上の話で、UI の実務での普及が未確認。または X の反応が小さい |
| 低 | 根拠がほぼ 1 件で、反応も小さい |
| 未確認 | 本文や URL を確認できなかった、または期間内の根拠が足りない |

低、低〜中、未確認は、採用の前提にしません。反対の見方があるときは確度を上げず、本文のソースに残します。

## 状態

本文の記述から、次のどれかを 1 つ付けます。理由は更新履歴の 1 行に書きます。

| 状態 | 付けるとき | latest.md |
|---|---|---|
| rising | 直近月で言及や反応が増えている、またはその月に新しく広がった | 残す |
| steady | 続いているが、急増とは書けない | 残す |
| mature | 定番化している。タグ `#mature` を検討する | 残す。差別化の根拠にはしない |
| fading | 前月まであった言及が落ちた、または「もう古い」という一次情報がある | 残す。状態を fading と書く |
| dropped | 根拠が否定された、別 ID と重複、見送りに落とした | 外す。index と本文は残す |

fading と dropped のファイルは削除しません。ID は欠番のまま残します。

## 更新する順

1. `x-findings-YYYY-MM.md` を受け取る。無い場合は、その旨を月次ファイルに書く。
2. Web（業界レポート、公式ドキュメント、論文）を調べ、投稿 URL の主張と突き合わせる。
3. 既存 ID に足すか、新しい手法なら次の空き ID を 1 つ取る。次の空きは [index.md](index.md) に書いてあります。初版の次は T19 です。ID の付け替え、統合による欠番の再利用はしません。
4. `trends/Txx-<slug>.md` を更新する。書式は ID、タグ、概要、特徴・適用方法、向く場面、避ける場面、代表例、ソース、トレンド時期、確度、状態、更新履歴です。スラッグは ASCII のまま変えない。ソースの URL、反応数、留保は消さない。数値が変わったときは、古い行を消さずに更新履歴へ「前の値と日時」を残す。
5. 新規は `trends/Txx-<slug>.md` を足す。
6. [index.md](index.md) のタグ索引と ID 索引を、全月が残る形で更新する。時期、確度、状態、初出、最終更新を直す。最終更新はその月にする。初出は項目を立てた月のままです。
7. [latest.md](latest.md) を、その月の要約だけに差し替える。各行は ID、一文の要旨、状態、確度、本文へのリンクです。dropped は載せません。
8. `monthly/YYYY-MM.md` を書く。検証方法、その月に集めたもの、見送りと保留、X 入力の有無、次の空き ID。

項目の編集は `docs/design-trends/` だけです。install.sh が配るコピーは `node scripts/build.mjs` の生成物なので、手で直しません。

## 月次ファイルに必ず書くこと

- 記録日（JST）と、反応数を取った時刻
- Web で見た資料の範囲
- X 入力ファイルを使ったか。使った場合は収集者と収集日時。使っていない場合は「X は未更新」
- 新規 ID、状態を変えた ID、見送りと保留
- 次の空き ID
