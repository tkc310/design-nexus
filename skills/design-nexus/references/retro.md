# Retro: turning feedback into durable learning

Run when the user reacts to a design ("too busy", "I like the type", "this doesn't feel like us"), or at the end of a session.

1. **Restate** the feedback as a concrete observation tied to a token, rule, or pattern ("Accent used on 7 elements; user found it busy").
2. **Classify** it:
   - *Project taste* → belongs in this project's `DESIGN.md` → *Learnings* (e.g. "Prefers dense tables over cards").
   - *Skill gap* → a rule this skill should have caught or a default that is wrong in general → record in the skill's feedback log.
3. **Write it down.**
   - Project: append under `## Learnings` in DESIGN.md with the date: `- 2026-10-30: Accent limited to primary CTA and data highlights (user: "too busy").`
   - Skill: if the skill repository is available, append to `loop/feedback.md` using its template. Otherwise include a ready-to-paste entry in your reply so the user can file it.
4. **Apply** the learning to the current work if it's still open.

Do not generalize one user's taste into a skill rule. A skill-gap entry needs a reason it applies beyond this project.
