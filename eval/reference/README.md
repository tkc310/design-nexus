# 参照ページ(V4、M-020)

尺度 v2 の「95点」に、外から見た意味を与えるための手順です。腕のよいチームが作った公開ページを、私たちのページと同じ審査(`eval/judge-prompt-v2.md`)にかけ、両方で判断できる次元(D2〜D7 と D9、`sub`)を比べます。換算式は作りません。差を読むだけです。

## 何を確かめるか

- **反証の条件(先に決めておく)**: 参照ページの `sub` の平均が、v0.10.0 の私たちのページの `sub` の平均を上回らなければ、v2 はプロの仕事を高く評価できていない。そのときは「95点」の読み方を保留し、基準を見直す。
- 上回るなら、その差が「95まで残っている距離」の目安になる。参照ページが 95 付近なら、95 は「この種類のページでの、プロの水準」と読める。参照ページでも 85 前後なら、95 はプロより上を求めている。
- D1・D8・D10 は比べない。参照ページの brief はページから書くので D1 は甘くなり、状態とコード(D8・D10)は外から見えないため。

## 選び方(採点の前に固定する)

1. 候補は `refs.json` の順番で固定している。ケースの種類(面と言語)ごとに、上から順に、ログインの壁と画面をふさぐ同意ダイアログがないものを2件使う。読み込めない・ふさがれている候補だけを、次の候補に替える。点を見てから入れ替えない。
2. 03(和文のダッシュボード)と 05(和文のスマートフォン向け時刻表)には、ログインなしで見られて、作りのよさで広く知られた公開ページが見つからないので、比べない。比べるのは 01・02・04・06 の種類。
3. ブランドの評判で選ばない。審査のプロンプトは評判を加点も減点もしないように指示している。

## brief の書き方

- 審査の前に、ページを見て書く。形は `eval/cases/` と同じにする。何のページか、誰に向けたか、ページの1つの仕事、ページに載っている事実(2〜4文)。
- ページの良し悪しや、デザインの特徴は書かない(審査を誘導しないため)。
- `refs.json` の `brief` に書く。空の候補は `ref` が受け付けない。

## 撮影と審査の手順

ネットワークが要ります。この環境のネットワーク方針では、候補のホストへの接続が拒否されます(2026-11-01 時点)。使うには、候補のドメインを許可したクラウド環境でセッションを開きます(Project settings → Cloud environment → Add cloud environment で、Allowed domains に候補のホストを足す。手順は https://code.claude.com/docs/en/cloud-environments#network-access)。

```bash
# 1. 使う候補の brief を refs.json に書く(上の「選び方」の順で2件ずつ)
node eval/run.mjs ref --only r01-astral,r01-bun,r02-kaikado,r02-asahiyaki,r04-govuk-ero,r04-govuk-pattern,r06-basecamp,r06-linear
# 2. 撮影(320・768・1280・1920 の第1画面とタイル。生きたページを開くので、日をまたがず1回で撮る)
node eval/run.mjs score --run <ref run>
#    shots を開き、同意の帯やログインの壁で中身が見えないページは、次の候補に替えて 1 からやり直す
# 3. 審査プロンプト。各ページを新しいコンテキストの Opus に渡し、judge-v2.opus.json に保存する
node eval/run.mjs judge --run <ref run> --scale v2
node eval/run.mjs score --run <ref run>
# 4. 私たちのページと比べる(v0.10.0 の base を v2 で審査したあと)
node eval/run.mjs ref-compare --ref <ref run> --base <base1>,<base2>,<base3>,<base4>
```

- 参照ページは `CASE.md` に url を持つので、lint とコードの読み取りはなく、審査は画面だけで D2〜D7 と D9 を決め、D1・D8・D10 を `null` にする(judge-prompt-v2.md の *Reference pages*)。
- 参照の run は history.jsonl に書かない(版の記録ではないため)。
- 結果は `loop/method.md` の M-020 の check に書く。撮影日と候補の入れ替えも書く。

## ネットワークが使えないとき

V4 は任意です。代わりに、較正セットの中で最も高いページ(v2 で上位のページ)の、落ちた基準を読みます。これは内部の上限でしかなく、95 の外から見た意味にはなりません。
