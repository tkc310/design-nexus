Find the slow errors in every log file at once.

grepline reads JSON and logfmt lines across as many files as you give it and keeps the ones your filter says to.

Homebrewbrew install grepline
Cargocargo install grepline

Try a filter on ten log lines from four files

Try

      A filter is a field, an operator, and a value.

      Join conditions with and or or. Numbers compare as numbers, so latency_ms>500 means more than half a second, not text that sorts after “500”. A line without the field simply doesn’t match.

      Tested against this line level=error service=checkout status=502 latency_ms=1240
      What each filter does with the line shown
      FilterReads asResult
      level=errorlevel is exactly “error”Keeps
      latency_ms>500latency_ms is a number above 500Keeps
      status<500status is a number below 500Skips
      service=search or status>=500either side holdsKeeps
      level=error and service=searchboth sides holdSkips

      Pass the filter first, then every file you want read.

      Output, one matching line each, prefixed with its file

      1. logs/api-01.jsonlevel=errorservice=checkoutlatency_ms=1240msg="payment gateway timeout"
      2. logs/api-02.jsonlevel=errorservice=searchlatency_ms=611msg="index not ready"
      3. logs/api-01.jsonlevel=errorservice=checkoutlatency_ms=3002msg="inventory lookup timed out"
