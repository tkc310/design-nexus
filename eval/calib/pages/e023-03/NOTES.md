# NOTES — 今月の給与ダッシュボード(クリニック向け給与計算SaaS)

Budget: standard / mode: build / surface: product

## Grounding

- Subject: 小規模クリニック(15〜40名)の月次給与。勤怠締め → 勤怠承認 → 給与確定 → 振込。
- Audience: 事務長・院長。給与の専門家ではなく、診療の合間に作業する。締め日の見落としと支給額の誤りを恐れている。
- Job: 締め日までに今月の給与を**確定する**。
- Primary action: 「勤怠を承認する」。「給与を確定する」は未承認の申請が残っているあいだは同じ位置に置いたまま無効にし、理由を横に書いている。承認が済むと「給与を確定する」が塗りのボタンになり、「勤怠を承認する」は無効になる。

## Three directions considered

- A — 「検印欄」: 日本の事務書類の押印欄と、承認印(認印)・データ印を借りる。白い明細用紙と罫線の箱、朱の印。工程の箱と押印の列が画面を引っ張る。(明るい無彩色 / 明朝ディスプレイ+UDゴシック / 罫線パネル+薄い影)
- B — 「締め日の暦」: 診療カレンダー(休診日の印つき月めくり)を借りる。中間調の地に丸ゴシック、締め日・支給日・休診日を載せた月の帯が主役。(中間調 / 丸ゴシック / カード)
- C — 「シャウカステン」: 読影用ライトボックスを借りる。暗い地に数字が光る、等幅主導の高密度一覧。(ダーク / 等幅主導 / 発光する数字 / 高密度)。いつもの自分なら選ばない方向として出した。

**Chosen: A.** このプロダクトでユーザーがすることは「承認」と「確定」で、日本の事務ではどちらも文字どおり押印なので。B は締め日を見せるのは得意だが、承認の進み具合を伝える手段がない。C は医療らしさをレントゲン室から借りているが、給与業務は読影ではなく事務作業で、明るい事務所で一日中開いておく画面には重すぎる。

アクセントの候補: 朱肉の朱(約8°、承認印)/ 医院の看板のティール(約175°)/ 振込の銀行ネイビー(約225°)→ 朱に決めた。朱は「押印=確定」と同じ意味を持っていて、それがこの画面の主要アクションだから。ティールなら医療っぽいが、どのクリニック向けアプリにもある色。ネイビーは給与を「銀行」側から見た色で、承認する人の目線ではない。
ディスプレイ書体の候補: Shippori Mincho B1(明朝、印と明細書のタイトル)/ BIZ UDPGothic(UDゴシック、帳票と院内サイン)/ IBM Plex Mono(等幅、ドットインパクトで印字した帳票)→ 明朝に決めた。給与明細書の見出しと印面の文字がこの字形だから。本文は BIZ UDPGothic、数字は等幅数字の BIZ UDGothic。

## Signature

**検印欄。** 構成単位は押印欄(緑の見出し帯がついた罫線の箱)と朱の印(承認者の姓を縦書きにした円形の認印、確定には上段「確定」・中段日付・下段氏名のデータ印)。同じ単位を次の場所で使い回している。
1. 工程の箱 — 締め日まで(残り日数)/ 勤怠の承認 / 給与の確定(空のデータ印 → 確定すると押される)/ 支給日。
2. 「勤怠の承認」の箱の中に、スタッフ1人につき小さな印を1つ並べた列(25/30 が承認済み)。
3. 一覧の「勤怠」列 — 承認済みの行には「小野」の認印(行ごとに少し傾けて手で押した感じを出す)。未承認の行は点線の「未」(押すと承認ダイアログが開く)。打刻を取り込めていない行は朱の点線の「!」。
4. 合計のパネル — 明細書の支給/控除欄と同じ見出し帯の箱。
5. 確定ダイアログ — これから押すデータ印を見せる。

一覧の縞は連続帳票(グリーンバー用紙)の緑から取った。

## States and how to reach each

- 既定の表示(代表的な状態): 未承認の申請5件(4名)、打刻を取得できていない1名(清水 早苗)、今月入職の1名(前月比「今月入職」)、長い名前1名(ファン・ティ・ミン・アイン)。承認待ちの行の差引支給額には「仮」がつく。
- 行単位のエラー: 清水 早苗の行の「再取得する」→ 0.9秒後に取り込まれ、印が押され、合計が更新される。
- 承認: 「勤怠を承認する」または行の点線の「未」→ ダイアログで申請を選ぶ → 「選んだN件を承認する」→ 印が押されるアニメーション、トースト「N件の申請を承認しました」、承認した残業代が支給額に加算される。
- 確定: 承認と再取得が済むと「給与を確定する」が押せる → 確認ダイアログ → 「確定する」→ データ印が押され、トースト「11月分の給与を確定しました」。
- 読み込み中: 前月・翌月の切り替え(0.7秒のスケルトン。最終的なレイアウトと同じ形)。
- 0件: 「12月分」へ移動する(まだ作られていない月)。さらに「氏名で探す」で一致しない名前(例「鈴木」)を入れると、絞り込みの0件になり「絞り込みを解除する」が出る。
- エラー: オフラインにして(DevTools → Network → Offline)月を切り替える、または「もう一度読み込む」を押す →「N月分の給与データを読み込めませんでした」と復旧の手順。オンラインに戻して「もう一度読み込む」を押すと復旧する。
- 過去の月(10月以前): 確定済みとして表示し、すべての行に印、データ印も押されている。

## Assumptions and invented content

- 製品名「給与ノート」、医院名「さくら通り内科クリニック」、承認者「事務長 小野 由紀子」、スタッフ30名の氏名・職種・金額、申請5件の内容はすべて架空。実在の人物・団体を指すものではない。
- 給与のサイクルは20日締め・当月25日払いと仮定した。デモの「今日」は 2026年11月14日(土)に固定していて、残りは6日。
- 控除は総支給額の約19〜25%で簡易に計算した(社会保険料・源泉所得税・住民税を合わせたもっともらしい値で、制度どおりの計算ではない)。
- 前月比は前月にも在籍したスタッフだけで比べる。人件費が増えることは悪いことではないので、赤/緑は使わず符号(+/−)だけで示した。
- 打刻を取得できていない1名は、合計から外したうえでそのことを明記した。
