Filter logs by field, not by regex.

grepline reads JSON and logfmt across every file you point it at and keeps the lines where level=error and latency_ms>500.

$ brew install grepline
$ cargo install grepline

One Rust binary. MIT licensed.

Then run your first search:

$ grepline 'level=error and latency_ms>500' ./logs/
$ grepline
./logs/

3 of 12 lines matchapi.jsonl · auth.log

No line in ./logs/ matches .

    If you can write a WHERE clause, you know the syntax.

    Name a field, compare it, combine with and, or, not and parentheses. Numbers compare as numbers, so latency_ms>500 means what it says. A line that lacks the field simply doesn't match.

    Filter operators
    WriteKeeps lines whereExampleRun in the filter above
    = != the field equals, or doesn't equal, the value level=error
    > >= < <= the number is above or below the value latency_ms>500
    and both conditions hold level=error and latency_ms>500
    or either condition holds status=502 or status=504
    not ( ) a condition fails, or a group decides first service=checkout and not (status<300)

    One service writes JSON, the next writes logfmt. Same filter.

    Fields are fields. Point grepline at a directory of mixed services and one expression reads both, then prints every match in the same line shape.
