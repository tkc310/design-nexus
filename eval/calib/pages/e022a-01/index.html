Search the fields, not the text.

grep finds error. It can't find errors slower than 500 ms. grepline reads JSON and logfmt lines from every file you name and keeps the ones that match level=error and latency_ms>500.

  • $ brew install grepline
  • $ cargo install grepline

written_in=rust license=MIT binaries=1

$ grepline ' ' logs/*.log

Compare any field with = != > < >= <= and join conditions with and / or.

Filters read like a WHERE clause.

If you can write the bottom half of a SQL query, you can write a grepline filter. Numbers compare as numbers, so latency_ms>500 means milliseconds, not text that sorts after "500".

  • level=error

    level is exactly error.

  • status!=200

    status is anything but 200.

  • latency_ms>500

    latency_ms is a number above 500. Also >=, < and <=.

  • level=error and latency_ms>500

    both are true.

  • level=warn or level=error

    either is true.

  • (level=warn or level=error) and status>=500

    parentheses group conditions, as in SQL.

  • msg="smtp timeout"

    quote a value that contains spaces.

JSON lines and logfmt, one filter for both.

Your API logs JSON, your workers log key=value. Name both kinds of file in the same run; the field names are what the filter sees.

Install grepline.

written_in=rust license=MIT binaries=1

  • $ brew install grepline
  • $ cargo install grepline

Then point it at last night's logs:

  • $ grepline 'level=error and latency_ms>500' logs/*.log
