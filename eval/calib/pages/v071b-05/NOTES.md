# NOTES — 05 mobile transit(かやのん号 時刻表)

Budget: standard / surface: mobile / mode: build。成果物は `index.html`(単一ファイル、CSS/JS はインライン)と `DESIGN.md`。

## 前提(質問できなかったので、こう決めた)
- 架空の「かやの市コミュニティバス かやのん号」。かやの駅を起点に、一方向で回る循環路線(11 停留所、一周 38 分)。
- 時刻はかやの駅の発車時刻 + 各停留所までの所要分で計算する。平日 23 便、土日祝 13 便。
- 土日祝ダイヤは、土日・2026〜27 年の祝日・年末年始(12/29〜1/3)に適用。
- 運休のお知らせは「本日、かやの駅を 13時台・14時台に出る便を全区間運休(市民病院前の水道管工事)」。実際の製品なら配信データから来る内容を、ページの日付に合わせて生成している。
- 時刻は端末の時計(現地時刻)で計算。15 秒ごと、および画面に戻ったときに更新。
- 選んだ停留所と文字の大きさは localStorage に保存(使えなくても動く)。

## 創作した事実(すべて架空)
市名「かやの市」、愛称「かやのん号」、停留所名と所要分、全時刻、運休の理由と時間帯、「6:00 更新」、問い合わせ先「かやの市役所 都市交通課(平日 8:30〜17:15)」、2026年10月1日改正。電話番号と運賃は、実在しそうな値を作らないために載せていない。

## 3 つの方向
A —「停留所の時刻表板」: バス停のポールに付いた白い時刻表板と、車体の黄色い帯を借りる。黄帯の「時」セル + 分の並びという時刻表行がページを組む。明るい・UD ゴシック + 交通標識系のコンデンス数字・実際の厚みのある板。
B —「車内 LED 行先表示」: 車内前方の LED 表示器(黒地にアンバーの点字体)を借りる。暗い地・点字体/等幅・発光。次の便がスクロール表示されるような大きなカウントダウンが主役。
C —「回数券」: 車体色の飽和した地に、回数券の券面カードと丸ゴシック。親しみと手ざわりが主役。

**採用: A。** 高齢の利用者がいちばん見慣れていて、屋外の日中でも読める形が「停留所の時刻表板」そのものだから。B は夜の雰囲気は強いが日中の屋外で読みにくく R04b に近い。C は全時刻表を券面に収められず、上下で別物になる。

アクセント候補: 車体の黄 #F5C400(採用。利用者が遠くから見分ける色で、地として使い文字色には使わない)/ 路線図の青(インクブルーはエージェントの定番に寄る)/ 待合所の屋根の緑(「正常」の状態色と紛れる)。
表示書体候補: BIZ UDPGothic(公共サインの UD ゴシック)/ Zen Maru Gothic(丸ゴシック)/ Shippori Mincho(貼り紙の明朝) → 数字は交通標識系の Barlow Semi Condensed、和文の見出しと本文は BIZ UDPGothic。

## シグネチャー
黄帯に「のりば + 停留所名 + ◯◯方面」を掲げた「次の3本」の板。最初の 1 本は「あと 12 分」を最大サイズ(57px、大きく設定で 69px)で出す。運休の便は 3 本に数えず、打ち消し線の 1 行として間に残す(連続する運休は 1 行にまとめる)。同じ板と時刻表行の単位で、運休の貼り紙(赤い帯)と当日の全時刻表(黄帯の「時」セル + 分)を組んでいる。

## 状態と、その出し方
- 通常: 運行時間中は「次のバス / 2本目 / 3本目」と「あと◯分」(60 分以上は「あと◯時間◯分」、0 分は「まもなく発車」)。
- 運休が次の 3 本の間にある: 13〜14時台の運休便が打ち消し線の行で出る(例: 平日 12:38 のかやの駅)。
- 運行終了後: 「今日のバスは終わりました。明日◯月◯日(◯)は◯◯の時刻表で走ります。」を先に出し、「明日の始発」から 3 本を数える。
- 曜日の切り替え: 「表示する曜日」で今日と違う曜日を選ぶと「◯◯の時刻表を表示中です。今日は◯◯です。」と「今日の時刻表に戻す」が出る。今日以外の表には発車済み・運休・次の便の印を付けない。
- 通信できない: 端末をオフラインにすると、貼り紙の中に「いま通信ができません…時刻表はこのまま見られます。」が出る。
- 文字の大きさ: 「大きく」で root を 18px → 22px に。320px でも横スクロールなし(確認済み)。
- ダークモード: `prefers-color-scheme: dark` で別パレット(次の便は黄地に黒の数字に反転)。

## デフォルト描画について(意図的な判断)
既定の render check は実行時刻(UTC 2026-10-31 土 19:4x)で描くため、運行終了後の状態(明日の始発から 3 本)が出る。craft.md は代表的な状態を既定にするよう求めるが、実際の利用者に「あと 7 分」と偽の時刻を見せるのは、この製品では危険なのでやめた。代わりに運行終了後も 3 本の表示が成り立つように作り、運行時間中の代表状態は `--tz Asia/Tokyo --time 2026-11-04T12:38:00+09:00` で固定した `shots-pinned/` で確認した。
