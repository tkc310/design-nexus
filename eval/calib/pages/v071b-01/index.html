Query your logs like a table: level=error and latency_ms>500

grepline reads JSON and logfmt lines across every file you point it at and keeps the ones that match a SQL-like filter. One Rust binary, MIT licensed.

$ brew install grepline

JSON and logfmt, one filter

Your API writes JSON, the billing worker writes logfmt. grepline parses each line into fields first, so the same expression runs across both without a jq step or a regex per format.

Both lines match level=error and latency_ms>500

The filter reads like a WHERE clause

Name a field, compare it, join conditions with and. Numbers compare as numbers, so latency_ms>500 never matches "latency_ms":"90" by string order. Lines without the field are skipped, not errors.

You writegrepline keepsRun it
level=errorLines whose level field equals error

Run it on your own logs

Pick the package manager you already have. Then point grepline at a directory and start with the filter you would have typed into a log dashboard.

  1. 1Install with Cargo or Homebrew 
    $ cargo install grepline
    $ brew install grepline
  2. 2Filter a folder of logs 
    $ grepline 'level=error and latency_ms>500' ./logs/*
