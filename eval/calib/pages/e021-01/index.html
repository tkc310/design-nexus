WHERE clauses for your log files.

grepline searches JSON and logfmt logs across many files with a filter you can read at 3am: level=error and latency_ms>500. One Rust binary, MIT licensed.

Install with Cargo

cargo install grepline

or Homebrew

brew install grepline

Then point it at a log directory, as in the pane below.

Try a filter on four log files

~/incident/logs
$ grepline ' ' *.jsonl *.log
Try:

If you can write a WHERE clause, you already know it.

Field names are the keys in your logs. Compare with =, !=, >, <, >=, <=; combine with and, or, and parentheses. Numbers compare as numbers.

FilterReads asIn paneLoad into pane
level=errorequals
status!=200not equal
latency_ms>500number compare
level=error and latency_ms>500both hold
service=billing or service=autheither holds
(level=warn or level=error) and service=billinggrouping

One filter, both formats.

The gateway writes JSON, the worker writes logfmt. Field names mean the same thing in both, so one run of status>=500 and service=billing finds the failure in each.

gateway.jsonl JSON lines

{"ts":"2026-10-30T02:14:07Z","service":"billing","route":"/v1/charge","status":502,"latency_ms":1240}

worker.log logfmt

ts=2026-10-30T02:14:07Z service=billing job=settle status=503 msg="upstream timeout"

The facts, as a log line.

name=grepline lang=rust license=MIT binaries=1 formats=json,logfmt source=open
