Your logs already have columns. Filter them.

grepline searches JSON and logfmt logs across many files with a filter you can read out loud: level=error and latency_ms>500.

brew install grepline
cargo install grepline

One Rust binary. MIT licensed.

    Filter syntax

    A where-clause, minus the table.

    Every structured log line is already a row of keys and values. grepline lets you ask for rows the way you would in SQL, straight from the shell.

    Fields are the keys you already log: level, status, route, whatever your services write.

    Compare with = or with > and friends, so latency_ms>500 means slower than half a second, not text that sorts after "500".

    Join clauses with and. Quote the whole filter in the shell so > reaches grepline instead of redirecting output.

    Formats

    JSON from one service, logfmt from the next. Same filter.

    Most fleets log in both. You write the filter once and point it at every file.

    JSON lines

    One object per line, as written by most app loggers.

    {"level":"error","ts":"03:12:41","svc":"checkout","latency_ms":1840,"msg":"upstream timeout"}

    logfmt

    Space-separated key=value pairs, common at the edge and in Go services.

    level=error ts=03:12:44 svc=edge latency_ms=30001 msg="gateway timeout" 
    $ grepline 'level=error and latency_ms>500' checkout.jsonl edge.log
