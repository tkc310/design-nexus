# NOTES — 03-dash-clinic（今月の給与ダッシュボード）

Budget: standard / Surface: product / Mode: build（DESIGN.md も新規作成）

## Ground
- Subject: 小規模クリニック（15〜40名）向け給与計算SaaS「こよみ給与」の「今月の給与」画面。
- Audience: 事務長・医療事務。会計の専門家ではなく、締めと振込遅れを恐れている。
- Job: 締め日までに勤怠を承認し、給与を確定する。

## 検討した3方向
- A —「勤務表の暦」: クリニックの勤務表のマス（曜日＋日付）を借り、勤怠期間の初日から支給日までの暦ストリップで締め日までの残りを見せる。明るい無彩色地、UDゴシック、フラットな罫線＋グリーンバーの表。
- B —「グリーンバー台帳」: 連続帳票の給与台帳（緑の帯、送り穴）を借り、スタッフ別の表そのものを主役にする。薄緑の地、等幅数字、高密度。
- C —「受付の呼出表示」: 待合室の番号表示板（暗い盤面にアンバーLED）を借り、残り日数と未承認件数を大きなLED数字で出す。暗地・高エネルギー（習慣外の方向）。

## 採用: A
事務長は毎月、勤務表と締め日・振込日の暦で仕事を組み立てている。「あと何日で何をすべきか」を彼らの語彙で一目に出せるのは A。B の帯は表の下地として取り込んだ。C は毎日長時間見る管理画面には強すぎ、アンバーが警告色と衝突するため却下。

アクセント候補: 帳票グリーン（給与台帳の罫）／朱肉の朱（承認印）／白衣・ステンレスのほぼ無彩色。→ 帳票グリーンを主色に。朱は主ボタンにすると「削除」に読めるので、「あなたの印が要るもの」（未承認・取り込みエラー）に限定。無彩色はアクションの目印にならない。
表示書体候補: BIZ UDPGothic（医療・公共の帳票と案内表示のUD書体）／Shippori Mincho（明細書の明朝）／等幅（帳票印字）。→ クリニックの掲示や保険関係の書類に近い BIZ UDPGothic。

## Signature
暦ストリップ（10/1〜11/10 の41マス）。今日（10/31）・締め日（11/5、塗り）・支給日（11/10、罫）を直接ラベルし、締め日までの残りのマスを帯色、未承認の申請がある日に朱の件数バッジ（押すとその申請へ移動）。単位は「暦のマス」で、承認待ちリストの各申請、取り込みエラー行の対象日（10/28–10/31）、確定ダイアログの締め日・支給日に同じマスを再利用。

## 状態と到達方法（すべて実際のフローで）
- 部分状態（初期表示に含む）: 未承認の申請5件、打刻の取り込みエラー1件（小林さん、「打刻をもう一度取り込む」で解消）、10月入社1名（前月比「新規」）。
- 読み込み中: 見出し横の「‹ 9月分」「11月分 ›」で月を切り替えると、表・申請・前月比がスケルトンになる（約0.65秒）。
- 0件: 「11月分 ›」で未作成の月（スタッフ0件の空状態）。申請をすべて承認すると「未承認の申請はありません」。氏名で一致しない文字を入れると絞り込みの空状態。
- エラー: オフライン（DevTools の Network → Offline）で月を切り替えるか再読み込みすると「給与データを読み込めませんでした」＋「もう一度読み込む」。オフライン中の打刻再取り込みもトーストで失敗を伝える。
- 確定: 未承認・エラーが残る間は「まだ確定できません」ダイアログ（解消先へ移動）。解消後は確定ダイアログ→「確定しました」トースト→「確定を取り消す」で戻せる。9月分は確定済み（閲覧のみ）。

## 仮定と創作した事実（画面には書いていない）
- 「今日」は 2026-10-31（土）に固定（勤怠期間の最終日＝代表的な状態）。締め日は給与確定の期限として 11/5(木) 17:00、支給日 11/10(火)、末締め翌月10日払い。
- クリニック名「みなと内科・小児科クリニック」、製品名「こよみ給与」、スタッフ24名の氏名・職種・基本給・残業時間・控除率、申請5件の理由、事務長「田村」はすべて創作。控除は簡略化した率（常勤約21%、医師27%、パート7〜12%）で計算、残業代は基本給/160×1.25×時間。
- 祝日: 10/12、11/3 を休診日として表示。8月分以前は「前のシステムから移行していない」という設定。

- R08（tokens-check のみ）: 色トークン11個。基本7色＋状態色2（朱・朱の淡色）＋グリーンバーの帯＋休診日のマス。帯と休診日は暦と表の意味を担う題材由来の色で、削ると signature が成り立たないため残した。コード内の hex は DESIGN.md のトークンと一致（lint R08/N09 は0件）。

## 批評ラウンドで直したこと
1. 1280/1920 でも暦が横スクロールしていた（1fr 列が最広ラベルに揃っていた）→ 列数×最小幅で min-width を指定し、全41マスが一画面に収まるように。
2. 1280 で表がパネルからはみ出していた（R17）→ サイド列を340pxに、セル余白を8pxに（1440px以上で戻す）。
3. 承認待ちの各項目が狭く職種が途中で折れていた → 承認ボタンを氏名の行に上げ、内容を全幅に。前月比の帳簿の行見出しを短く。
4. 狭幅で暦が今日も支給日も見えない位置で始まっていた → 今日から支給日まで（入らなければ今日から）見える位置へ初期スクロール。
5. 9月分で `hidden` が `.btn` の display に負けてボタンが残っていた → `[hidden]` を強制。
- 外したアクセサリ: 凡例の「今日」（マスに直接書いてあるため重複）。
