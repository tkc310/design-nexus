Search JSON and logfmt logs with a WHERE clause.

grepline reads every file you point it at and prints the lines that match a filter like level=error and latency_ms>500.

cargo install grepline
On macOS or Linux with Homebrew: brew install grepline

written_in=rustlicense=MITships_as="1 binary"reads=json,logfmt

Filter syntax

If you can write a WHERE clause, you can already write a filter. Field names are the keys in your logs.

FormExampleKeeps lines where
= !=level=errorthe field equals, or doesn't equal, the value
> < >= <=latency_ms>500the field is a number above or below the value
and or notlevel=error and not route=/healthconditions combine, with and binding tighter than or
( )(status>=500 or level=error) and env=prodthe grouped condition holds first
"…"msg="upstream timeout"the value contains spaces
a.bhttp.status>=500a key nested inside a JSON object matches

One filter for both formats

Mix JSON lines and logfmt in the same run. grepline reads each line into fields, then applies the same filter to all of them.

gateway.jsonl

{"level":"error", "route":"/v1/pay", "latency_ms":1500}

worker.log

level=error job=refund.sync latency_ms=2210

Both read as the same fields

level=errorlatency_ms=1500 | 2210route | job kept as written

So level=error and latency_ms>500 keeps both lines.
