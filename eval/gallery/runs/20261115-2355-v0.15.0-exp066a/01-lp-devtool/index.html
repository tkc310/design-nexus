JSON and logfmt, asked the same question.

Your services don't agree on a log format. The filter doesn't need them to: level and latency_ms are fields whether they arrive as JSON keys or logfmt pairs.

The same fields in a JSON line from api.log and a logfmt line from worker.log
fieldapi.log JSONworker.log logfmt
level"level":"error"level=error
latency_ms"latency_ms":812latency_ms=2310
msg"msg":"upstream timeout"msg="pdf render stalled"

If you can write a WHERE clause, you can write the filter.

  1. level

    A field name, spelled as it is in the line.

  2. =error

    The value that field must hold.

  3. and

    Both clauses must hold for a line to match.

  4. latency_ms

    A second field, from the same line.

  5. >500

    Greater than 500, so 812 matches and 95 does not.
