# Maintaining design-nexus

This repository is the source of the design-nexus skill. These instructions are for agents working **on the skill itself** (Codex, Cursor, and Claude Code via CLAUDE.md). Users of the skill install it with `install.sh`; see README.md.

## Layout

- `skills/design-nexus/` — the single source of truth: `SKILL.md`, `references/`, `scripts/`, `templates/`. Edit only here.
- `dist/` — generated by `node scripts/build.mjs` for Claude Code, Codex, and Cursor. Never edit by hand; it is gitignored.
- `eval/` — cases, rubric, judge prompt, fixtures, and `run.mjs`.
- `loop/` — the improvement procedure, feedback log, and experiment log.
- `docs/comparison.md` — research behind the design decisions.
- `docs/design-trends/` — monthly trend database. Do not load it from this file. The skill reads it only when the user wants current trends incorporated.

## Rules

- Run `node scripts/test.mjs` after any change to `scripts/` or `references/checks.md`. Add a fixture case for every new check and for every false positive you fix.
- Keep check IDs stable. A new check gets the next free ID in its tier and a row in `references/checks.md`.
- Keep `SKILL.md` under about 150 lines; move detail into `references/`.
- `SKILL.md` and `references/` are written in English for portability; human-facing docs (`README.md`, `docs/`, `eval/rubric.md`, `loop/`) are in Japanese.
- Every skill change that is meant to improve output goes through `loop/IMPROVEMENT.md`: one hypothesis, logged in `loop/experiments.md`, accepted only by `node eval/run.mjs compare`.
- On accept: bump `VERSION` and `.claude-plugin/plugin.json` version together, add a `CHANGELOG.md` entry, run `node scripts/build.mjs`.
- Judge runs happen in a fresh context, never in the session that generated the output.
